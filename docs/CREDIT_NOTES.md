# 매출채권 및 신용손실 주석 입력

매출채권의 순액 여부와 범위는 재무제표 주석에서 확인합니다. 손실충당금과 ECL 금액도 주석에서 가져와 JSON 파일에 입력합니다. 프로그램은 입력한 자료를 API 금액과 대조한 뒤 계산에 사용합니다.

## 입력 순서

1. `credit_notes.example.json`을 `credit_notes.local.json`으로 복사합니다.
2. 실제 분석의 `계정매핑` 시트 또는 `raw_snapshot.json`에서 기업 고유번호와 연도별 접수번호를 확인합니다.
3. 같은 접수번호의 연결재무제표 주석에서 매출채권 표와 손실충당금 표를 확인합니다.
4. 분석 시작 직전 연도부터 종료연도까지 기업·연도별 레코드 하나씩 넣습니다. 2023~2025 분석에는 2022~2025가 필요합니다.
5. 출처 URL, 주석 번호·표·페이지와 범위 확인 근거를 기록합니다.
6. 같은 원본 스냅샷에 `--credit-notes`를 붙여 재실행하면 API를 다시 조회하지 않고 주석 입력을 반영할 수 있습니다.

## 필드 정의

| 필드 | 의미 |
|---|---|
| corp_code | DART 고유번호 8자리 문자열 |
| year | 사업연도 숫자 |
| fs_div / currency | CFS / KRW만 허용 |
| scope | `total_trade`: 전체 매출채권 / `current_trade`: 유동 매출채권. 기타채권 제외 |
| reported_basis | `net`: 선택한 API 계정이 순액임을 확인 / `gross`: 총액임을 확인 / `not_available`: 해당 범위의 단독 계정이 없어 주석 금액을 직접 사용 |
| balance_date | `YYYY-12-31` |
| rcept_no | 실제 동일 공시의 접수번호 14자리 문자열 |
| gross | 기말 매출채권 총액. 충당금 차감 전 |
| allowance | 해당 매출채권에만 대응하는 기말 손실충당금. 양수 크기로 입력 |
| net | 기말 매출채권 순액. 총액−충당금과 대사 |
| ecl_expense | 당기의 매출채권 관련 순 ECL 비용. 환입은 음수 |
| writeoffs | 당기 충당금을 사용한 매출채권 제각. 양수 크기 |
| recoveries | 당기 회수액. 별도 참고 항목이며 자동으로 충당금에 가산하지 않음 |
| other_movements | 충당금의 기타 순변동. 증가 양수/감소 음수. 환율, 취득·처분 등 포함 범위 기록 |
| source_url | 해당 공시의 HTTPS URL |
| source_ref | 주석 번호·표·페이지 및 순액/범위 확인 근거 |

금액은 원 단위 문자열로 입력합니다. 표의 단위가 백만원이면 원으로 환산하고 `source_ref`에 원래 단위를 기록합니다. 확인되지 않은 값은 `null`, 공시상 0인 값은 `"0"`으로 구분합니다. 큰 금액은 Excel에서 반올림될 수 있으므로 공시 원문의 숫자를 기준으로 입력합니다.

## 총액·충당금 없이 순액만 확인한 경우

API 금액이 해당 범위의 순액임을 확인했다면 `reported_basis="net"`으로 설정하고, `gross`, `allowance`, `net`은 `null`로 둘 수 있습니다. `source_ref`에는 이를 확인한 주석 위치를 적습니다. 이 경우 API 금액으로 순액 회전율을 계산하며, 총액 회전율과 충당금 설정률은 빈칸으로 남습니다.

회전율 계산에는 기초와 기말 자료가 모두 필요합니다. 주석 입력 후에도 기간과 분모 조건을 충족해야 합니다.

## 매출채권과 기타채권이 합산된 경우

주석에서 매출채권만 분리한 총액·충당금 또는 순액을 확인해 입력하고, `reported_basis="not_available"`로 설정합니다. 이때 계산에 사용한 주석 위치를 함께 기록합니다. 주석에서도 매출채권을 분리할 수 없으면 회전율은 계산하지 않습니다.

API에 단기 매출채권만 있고 비교 기준이 전체 매출채권이라면, 주석에서 전체 금액을 확인해 `not_available`로 입력합니다. API의 단기 금액을 전체 매출채권으로 사용하는 경우에는 범위 불일치로 처리합니다.

## 금액 대사와 결과 해석

- 총액과 충당금이 있으면 순액을 계산하거나 입력 순액과 비교합니다. 절대 오차 1원 초과는 불일치입니다.
- `net` 확인 대상인 API 금액과 주석 순액이 다르면 해당 주석을 회전율에 사용하지 않습니다.
- 충당금이 총액보다 크거나 음수로 잘못 입력되면 오류/검토 대상으로 처리합니다.
- 롤포워드는 기초 충당금, 당기 ECL 비용, 제각, 기타변동, 기말 충당금이 모두 있을 때만 수행합니다.
- 회수액을 롤포워드에 자동 더하지 않습니다. 해당 기업 회계처리와 실제 주석에 맞춰 기타변동에 포함할지 판단하고 설명하세요.
- 제각이나 매출채권 양도로 잔액이 줄면 현금 회수와 무관하게 회전율이 높아질 수 있습니다.

충당금 설정률을 비교할 때는 담보·보증, 연체기간, 고객 구성과 전망정보의 차이도 확인해야 합니다. 프로그램은 공시된 금액을 비교하며 ECL 모형의 손실률이나 충당금 적정성을 추정하지 않습니다.

## 예제와 테스트

입력 형식은 `examples/synthetic_demo/credit_notes.json`에서 확인할 수 있습니다. 이 파일은 가상 데이터입니다. `tests/test_credit.py`에서는 순액 이중 차감, 충당금 대사, 범위·공시 불일치와 출처 누락을 검사합니다.
